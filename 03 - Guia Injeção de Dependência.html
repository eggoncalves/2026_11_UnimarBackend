Injeção de dependência no C#

Os lifetimes Transient, Scoped e Singleton, com um simulador interativo.

Os tipos de lifetime

O container de DI do .NET (IServiceCollection) não decide apenas qual classe entregar. Ele decide também por quanto tempo aquela instância vive. Esse tempo é o lifetime, e existem três:

LifetimeQuando cria uma nova instânciaAnalogia
TransientA cada vez que alguém pedeCopo descartável: cada pedido ganha um novo
ScopedUma vez por escopo (no ASP.NET, uma por requisição HTTP)Mesa no restaurante: todos da mesma mesa dividem a garrafa d'água
SingletonUma única vez na vida da aplicaçãoO relógio da parede: todo mundo olha para o mesmo

Como registrar no Program.cs

builder.Services.AddTransient<IEmailFormatter, EmailFormatter>();
builder.Services.AddScoped<IPedidoRepository, PedidoRepository>();
builder.Services.AddSingleton<ICacheService, MemoryCacheService>();

Quando usar cada um

  • Transient: para serviços leves e sem estado, como formatadores, validadores e mapeadores. Como são baratos de criar, não há problema em gerar um novo a cada injeção.
  • Scoped: para tudo que deve ser compartilhado dentro de uma requisição e isolado entre requisições. O exemplo clássico é o DbContext do Entity Framework (AddDbContext já registra como Scoped): o Controller e o Repository enxergam a mesma unidade de trabalho e o mesmo controle de transação, mas o usuário A nunca compartilha contexto com o usuário B.
  • Singleton: para recursos caros de criar ou que precisam ser globais, como cache em memória, configurações e o HttpClientFactory. Atenção: o Singleton é acessado por várias threads ao mesmo tempo, então precisa ser thread-safe.
A pergunta que resume tudo: quem divide esta instância com quem? Ninguém divide (Transient), todos da mesma requisição dividem (Scoped) ou a aplicação inteira divide (Singleton).
