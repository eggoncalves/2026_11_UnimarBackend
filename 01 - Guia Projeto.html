Boas-vindas! O que vamos construir

Neste guia você vai construir, do zero, a API Unimar.ProjetoAcademico: um sistema acadêmico em .NET 10 organizado em camadas (Clean Architecture + DDD), com CQRS via Mediator, validações com FluentValidation, persistência em PostgreSQL (Entity Framework Core) e em Firebase Firestore.

Arquitetura em camadas

A solução é dividida em projetos. Cada um tem uma responsabilidade e só conhece as camadas de que realmente precisa. O resultado é um código mais fácil de testar, manter e evoluir.

01 · APIControllers REST, Program.cs, configurações. É a porta de entrada HTTP. Não contém regra de negócio.
02 · Application ServiceCasos de uso. Commands/Queries (Request + Handler + Validator + Response), AppServices que orquestram o fluxo e o contrato do Unit of Work.
03 · DomainCoração do sistema: entidades (Curso, Aluno, AlunoFb), enumeradores e interfaces de repositório.
04.1 · Infra.DataImplementações técnicas de acesso a dados: DbContext do EF Core, mapeamentos, migrations, repositórios (PostgreSQL e Firestore) e Unit of Work.
04.2 · CrossCuttingRecursos transversais usados por várias camadas: padrão de notificação, injeção de dependência (IoC), Mediator, FluentValidation e Swagger.

A história do .NET

Antes de escrever código, vale entender de onde vem a plataforma que vamos usar: por que ela foi criada, quem a criou e como passou de um framework só para Windows a uma plataforma open source e multiplataforma.

⏱ 20 min📖 Leitura

O contexto: o final dos anos 1990

No fim dos anos 1990, desenvolver para Windows significava lidar com C++ e COM, com o Visual Basic 6 ou com o ASP clássico (VBScript misturado ao HTML). Alguns problemas eram comuns:

  • “DLL Hell”: aplicações diferentes precisavam de versões diferentes da mesma DLL, e instalar um programa podia quebrar outro.
  • Gerenciamento manual de memória em C++, com vazamentos e falhas de segurança.
  • Linguagens isoladas: reaproveitar um componente VB em C++ (ou vice-versa) exigia o complexo modelo COM.
  • A web crescia rápido e a Sun promovia o Java, com a promessa de “escreva uma vez, rode em qualquer lugar”.

A Microsoft chegou a ter sua própria implementação de Java (Visual J++). Em 1997, a Sun processou a empresa por adicionar extensões incompatíveis à linguagem, e o acordo veio em 2001. Paralelamente, a Microsoft já desenvolvia internamente uma plataforma própria, chamada no início de Next Generation Windows Services (NGWS). Ela viria a ser o .NET.

Os criadores

👤 Anders Hejlsberg

Engenheiro dinamarquês, criador do Turbo Pascal e arquiteto-chefe do Delphi na Borland. Entrou na Microsoft em 1996 e liderou o design da linguagem C#, da qual segue como arquiteto-chefe. Mais tarde, criou também o TypeScript (2012).

👥 Equipe do C#

O design original do C# contou com Anders e com Scott Wiltamuth, Peter Golde, Peter Sollich e Eric Gunnerson. Internamente, o projeto começou com o nome “Cool” (C-like Object Oriented Language).

🌐 Scott Guthrie e Mark Anders

Criaram em 1997 o protótipo que deu origem ao ASP.NET (chamado inicialmente de “ASP+”). Scott Guthrie depois liderou a divisão de nuvem da Microsoft (Azure).

🔬 Don Syme

Pesquisador da Microsoft Research em Cambridge. Com Andrew Kennedy, projetou os generics do CLR (lançados no .NET 2.0) e depois criou a linguagem funcional F#.

🐒 Miguel de Icaza

Cofundador do GNOME. Em 2001 iniciou o Mono, implementação open source do .NET para Linux, e fundou a Ximian e, depois, a Xamarin (com Nat Friedman), comprada pela Microsoft em 2016.

⚡ Steve Sanderson

Criador do Knockout.js e, em 2018, do experimento que virou o Blazor: aplicações web interativas em C#, inclusive rodando no navegador via WebAssembly.

Ciclo de lançamentos: LTS x STS

Desde o .NET 5, sai uma versão nova todo mês de novembro, apresentada na .NET Conf:

🛡️ LTS (Long Term Support)

Versões pares (6, 8, 10…). Suporte de 3 anos. Preferidas em produção e em projetos corporativos. É por isso que usamos o .NET 10.

🚀 STS (Standard Term Support)

Versões ímpares (7, 9, 11…). Trazem novidades mais cedo. O suporte, antes de 18 meses, foi ampliado para 24 meses a partir do .NET 9.

ConceitoO que é
CLR (Common Language Runtime)A “máquina virtual” do .NET: carrega os assemblies, gerencia memória, segurança de tipos, exceções e threads.
IL / CIL (Intermediate Language)Código intermediário, independente de processador, gerado pelo compilador. Todas as linguagens .NET (C#, F#, VB.NET) compilam para ele, por isso conseguem usar os componentes umas das outras.
JIT (Just-In-Time)Converte IL em código nativo durante a execução, otimizando para a máquina real. O Tiered Compilation recompila os métodos mais usados com otimizações mais agressivas.
Native AOTCompila tudo para código nativo antes da execução: inicialização muito rápida e executável único, ideal para containers e funções serverless.
GC (Garbage Collector)Libera automaticamente a memória de objetos não usados, organizada em gerações (0, 1 e 2). Acaba com os vazamentos típicos do C++.
BCL (Base Class Library)A biblioteca padrão: coleções, arquivos, rede, JSON, LINQ, Task… Tudo o que usamos sem instalar pacotes.
CTS / CLSO sistema de tipos comum e as regras que permitem a interoperabilidade entre linguagens.
AssemblyA unidade de distribuição (.dll/.exe), com IL e metadados de versão. Cada projeto da nossa solução gera um assembly, e é isso que o AppDomain.CurrentDomain.GetAssemblies() enumera (Etapa 15).
NuGetGerenciador de pacotes do ecossistema (nuget.org), com centenas de milhares de pacotes.

🧠 Teste rápido

Quem liderou a criação da linguagem C#?

Anders Hejlsberg, que antes havia criado o Turbo Pascal e o Delphi e, depois, criou o TypeScript.

Por que não existe um “.NET 4” (sem “Framework”)?

Ao unificar a plataforma em 2020, a Microsoft pulou do .NET Core 3.1 para o .NET 5, evitando a confusão com o .NET Framework 4.x.

O que o compilador C# gera ao compilar o projeto?

O Roslyn gera IL dentro do assembly (.dll). Na execução, o JIT do CLR converte o IL em código nativo. Com Native AOT, essa conversão é feita antes, no momento da publicação.

Por que este projeto usa o .NET 10, e não o .NET 9?

Versões pares são LTS (3 anos de suporte). O .NET 9 é STS.

Padrão de Notificação (Notification Pattern)

Em vez de lançar exceções para erros de negócio (“curso não encontrado”, “e-mail inválido”), acumulamos notificações e decidimos no final o que responder. É a base sobre a qual todas as outras camadas se apoiam.

⏱ 20 min📁 NotificationPattern · ServiceNotification
💡 Conceito: por que não usar exceções?Exceções são caras e servem para situações excepcionais (banco fora do ar, bug). Erros de validação e de regra de negócio são esperados. Com notificações, conseguimos devolver todos os erros de uma vez, num formato padronizado, sem try/catch espalhados pelo código.

6.1 Projeto NotificationPattern

Crie as pastas DTOs e Interface dentro do projeto Unimar.ProjetoAcademico.Infra.CrossCutting.NotificationPattern.

Entenda o código
namespace ...;

class Notification(string property, string message)

{ get; private set; }
Leitura pública, escrita apenas dentro da classe. Garante que ninguém altere a notificação depois de criada.

⏱ 30 min📁 Domain · Infra.Data
Entenda o repositório Firestore
firestoreDb.Collection("alunos").Document(id)
Referência a um documento. Ainda não acessa a rede; o acesso só acontece em GetSnapshotAsync, SetAsync ou DeleteAsync.
snap.Exists
O Firestore não lança erro para Id inexistente: ele devolve um snapshot com Exists = false.
GetValue<T>("campo")
Lê um campo convertendo para o tipo C#. Os nomes dos campos são case-sensitive ("nome" ≠ "Nome").
AddAsync x SetAsync
Collection.AddAsync cria um documento com Id automático. Document(id).SetAsync escreve num Id conhecido; com SetOptions.MergeAll, mescla em vez de sobrescrever.
Map e MapList (DRY)
Don't Repeat Yourself: toda conversão documento → entidade passa por um único método Map. Incluir um campo novo exige alterar uma só linha, e é impossível “esquecer” o campo em algum método. Select(Map) é um method group, equivalente a Select(d => Map(d)). Outra opção são os atributos [FirestoreData]/[FirestoreProperty] com d.ConvertTo<T>().
TryGetValue("matricula", out var matricula)
Diferente de GetValue, que lança exceção se o campo não existir, o TryGetValue devolve false. Documentos gravados sem o campo continuam sendo lidos, com a matrícula vazia.
private static
Map e MapList não usam o estado da instância (firestoreDb), então podem ser static: são funções puras de conversão.
Índices
Consultas que combinam filtros/ordenações em campos diferentes exigem um índice composto. O erro retornado traz um link que cria o índice com um clique.

🧠 Revisão final

Onde acontece o SaveChangesAsync nas operações de escrita de Curso?

O handler só marca as alterações. O AppService chama unitOfWork.CommitAsync() se não houver notificações.

Por que o Program.cs chama InitApplicationService() antes de GetAssemblies()?

GetAssemblies() só retorna assemblies já carregados. Usar um tipo do assembly força seu carregamento.

Qual tempo de vida é usado para o FirestoreDb?

Singleton: uma única instância, thread-safe e cara de criar, reutilizada por toda a aplicação.
